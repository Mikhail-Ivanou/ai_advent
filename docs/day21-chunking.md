- «предложение → его место»: запрос — случайное предложение документа, попадание — чанк, содержащий это место, в top-k;
- «заголовок → его раздел»: запрос — заголовок раздела, попадание — чанк, который минимум наполовину состоит из этого раздела.

Корпус: ≈ 72 тыс. символов (≈ 40 страниц) — 4 статьи Википедии (HTML по ссылке) и 2 README (markdown).
Модель эмбеддингов: `Xenova/multilingual-e5-small` (384 измерения, лимит 512 токенов), локально.

## Выводы

- **Fixed** даёт ровные чанки (σ 121 символ), но 61% из них захватывают
  больше одного раздела, а 6% обрываются посреди предложения. Перекрытие
  дублирует около 18% текста. Лучше находит конкретное место текста по
  дословной фразе: чанки одинаковые и не размыты, а из-за перекрытия у
  каждого места два шанса попасть в выдачу.
- **Structural** держит тему: только 11% чанков объединяют несколько
  (коротких соседних) разделов, обрывов нет, а каждый чанк начинается с
  пути заголовков. Поэтому на вопросы «о чём раздел» (заголовок как запрос)
  он почти вдвое точнее: Hit@1 61% против 31%, MRR 0.66 против 0.36. Цена —
  неровный размер (49–1428 символов) и немного мелких чанков от коротких
  разделов, которые не с чем объединить.
- Лимит structural подобран под модель: при `maxSize` 1800 символов 12%
  чанков не помещались в 512 токенов и молча обрезались при эмбеддинге.
  1400 символов ≈ 400 токенов с заголовком.
- Для вопросов по смыслу («что такое механизм внимания») structural находит
  нужный раздел первым; fixed возвращает соседние куски, начинающиеся с
  середины фразы.
